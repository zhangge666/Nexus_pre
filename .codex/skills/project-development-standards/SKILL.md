# 项目开发规范

本文件规定项目开发全过程的文档依据、代码注释、UI 实现、验证和阶段提交要求。执行任何开发任务时，先理解现有代码与文档，再按以下流程实施并交付。

## 开发流程

1. 检查工作区状态、项目结构、`AGENTS.md`、README、架构文档、需求文档和与任务相关的源码。
2. 明确任务边界并划分可独立验收的开发阶段。小型任务可以只有一个阶段；不要为了增加提交数量而人为拆分。
3. 开发对接功能前，优先查阅项目内对应的开发文档；涉及框架、SDK、协议、外部软件或 API 时，再查阅其当前版本的官方文档。实现应贴合文档定义的字段、类型、生命周期、错误语义和推荐用法。
4. 修改前确认用户已有的未提交变更。不得覆盖、回退或混入与当前阶段无关的改动。
5. 完成功能、注释和必要测试。涉及界面时额外执行“UI 规范”。
6. 检查阶段差异，运行适合该阶段的格式化、静态检查、编译和测试。
7. 每个完整阶段验收通过后立即创建一次 Git commit；提交信息使用中文阶段标题或该阶段完成的主要内容。
8. 进入下一阶段前确认上一个提交成功。若测试失败或功能尚未闭环，不得以“阶段完成”名义提交。

## 代码注释

### 文件顶部

- 在每个新增的源代码文件顶部添加简洁的中文说明，解释该文件的主要内容、职责或模块边界。
- 修改缺少顶部说明的既有源文件时，在不违反语言约定、生成文件规则或许可证头要求的前提下补充说明。
- 保留 shebang、编码声明、许可证头和框架要求的特殊指令；文件说明放在这些内容之后的合法位置。
- 不修改自动生成文件来补充注释。应修改生成源或生成模板，并保留生成标记。

### 功能函数

- 为每个功能函数、方法、组件、Hook、接口处理器、任务入口等添加对应的中文注释，说明其用途。
- 对外 API 或逻辑不直观的函数，补充关键参数、返回值、副作用、异常或边界条件。
- 简单回调、框架约定的样板函数或仅做直接转发的函数，可使用一句简短注释，避免重复代码字面含义。
- 使用当前语言和仓库既有的文档注释格式，例如 JSDoc、TSDoc、docstring、JavaDoc 或 Rust doc comment。

### 复杂逻辑

- 函数包含复杂分支、状态转换、算法、并发、缓存、兼容处理、协议映射或非显然业务规则时，在关键代码块前添加中文行内注释。
- 注释重点解释“为什么这样处理”、业务约束和容易误改的条件，不逐行翻译代码。
- 代码变更后同步更新注释，禁止保留与行为不一致的说明。

## 文档对接

- 先定位与当前模块、接口或业务流程直接相关的项目文档，并核对实现与文档是否一致。
- 涉及第三方能力时使用对应版本的官方文档作为首要外部依据；不要仅凭记忆或非官方示例确定接口行为。
- 项目文档与实际代码冲突时，先确认版本、迁移状态和现有测试。无法判断时向用户说明冲突，不擅自扩大修改范围。
- 若任务改变公开接口、配置、数据结构或用户流程，应同步更新对应开发文档。

## UI 规范

- 开始任何界面设计或实现前读取仓库根目录的 `docs/design-system.md`，并将其作为 UI 的唯一项目级视觉规范。
- 优先复用项目既有组件和 design token；不得绕过规范硬编码颜色、间距、圆角、阴影或动效。
- 按设计文档落实组件选型、布局密度、排版、交互状态、响应式行为、键盘操作、焦点可见性和 `prefers-reduced-motion`。
- 新需求无法由现有 token 或组件表达时，先按项目流程扩展设计系统，再在业务界面中引用。
- 完成后在目标桌面和移动视口检查文本溢出、元素重叠、交互状态和视觉一致性。

## 阶段提交

- 将“完整阶段”定义为可独立说明、已实现、已验证且不会留下已知半成品的工作单元。
- 提交前使用 `git status` 和 `git diff` 核对内容，只暂存当前阶段相关文件。
- 使用中文提交信息，优先采用简洁的阶段标题或主要完成内容，例如 `完成用户认证接口对接`、`实现工作台响应式布局`。
- 不使用 `阶段一`、`更新代码`、`fix` 等无法说明内容的模糊信息。
- 不修改、压缩、重写或合并用户已有提交，除非用户明确要求。
- 若仓库无法提交（例如缺少 Git 身份、权限受限或钩子失败），保留已完成改动并准确报告原因，不伪造提交成功。

## 完成检查

- 确认新增和修改的源文件顶部具有中文职责说明。
- 确认每个功能函数具有对应的中文注释，复杂逻辑具有必要的中文行内注释。
- 确认实现贴合项目开发文档和所用软件、框架或 API 的官方文档。
- 确认所有 UI 改动遵循 `docs/design-system.md`。
- 确认测试、检查或构建结果已记录，未执行的验证明确说明原因。
- 确认每个已完成阶段均有独立的中文 Git commit，且未包含无关变更。
