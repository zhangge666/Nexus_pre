# Nexus 设计系统 · Linear 式工作台

本文件定义 Nexus 产品家族的统一视觉、布局和交互规范。其参考对象是 [Linear](https://linear.app/) 的产品工作台体验：**内容优先、信息致密、层级清晰、交互安静且快速**。本文件是 Orbit、Echo、Muse、Quill 及共享 UI 包的唯一项目级设计依据。

> 目标不是复刻 Linear 的品牌、文案、图标或页面，而是采用其可用性原则与工作台结构，形成 Nexus 自己的记忆管理界面。

---

## 1. 体验原则

1. **工作优先**：首屏直接呈现可操作的数据与下一步动作；装饰不能抢占内容空间。
2. **单一主焦点**：每个页面只有一个主要任务（检索、阅读、编辑、整理），其余操作退居次级层。
3. **密而不挤**：以紧凑行高、稳定列宽和弱分隔线组织信息，而不是堆叠大卡片。
4. **渐进揭示**：详情、批量操作、筛选和次要元数据按选中、悬停或快捷键需要出现。
5. **键盘同等重要**：所有高频动作均应有清晰焦点、可达控件和快捷键入口。
6. **可靠反馈**：写入、同步、筛选、错误和离线状态必须在原位置以低干扰方式反馈。

## 2. Token：唯一真相

组件内禁止硬编码颜色、间距、圆角、阴影和动画参数。所有值必须引用以下 CSS 自定义属性；需要新增 token 时先修改本文件与 `@nexus/ui`。

### 2.1 暗色默认主题

```css
:root, :root.dark {
  --background: 222 15% 7%;
  --surface: 222 14% 9%;
  --surface-elevated: 222 13% 12%;
  --surface-hover: 222 12% 15%;
  --surface-active: 234 44% 18%;
  --muted: 222 11% 17%;

  --foreground: 220 16% 94%;
  --foreground-secondary: 220 10% 69%;
  --foreground-muted: 220 8% 48%;
  --foreground-disabled: 220 7% 34%;

  --border: 220 12% 100% / 0.09;
  --border-strong: 220 12% 100% / 0.16;
  --border-subtle: 220 12% 100% / 0.055;
  --ring: 234 62% 65%;

  --primary: 234 62% 65%;
  --primary-hover: 234 68% 71%;
  --primary-foreground: 0 0% 100%;
  --success: 145 48% 50%;
  --warning: 39 90% 58%;
  --danger: 0 66% 60%;
  --info: 204 78% 58%;

  --radius-sm: 4px;
  --radius: 6px;
  --radius-md: 8px;
  --radius-lg: 10px;
  --radius-xl: 16px;
  --shadow-sm: 0 1px 2px rgb(0 0 0 / 0.28);
  --shadow-md: 0 10px 28px -8px rgb(0 0 0 / 0.48);
}
```

### 2.2 亮色主题

亮色是 opt-in；仅覆盖 token，组件不应包含暗/亮主题判断。

```css
:root:not(.dark) {
  --background: 220 20% 98%;
  --surface: 0 0% 100%;
  --surface-elevated: 0 0% 100%;
  --surface-hover: 220 16% 96%;
  --surface-active: 234 62% 94%;
  --muted: 220 15% 94%;
  --foreground: 220 18% 15%;
  --foreground-secondary: 220 10% 38%;
  --foreground-muted: 220 8% 52%;
  --foreground-disabled: 220 7% 66%;
  --border: 220 14% 15% / 0.11;
  --border-strong: 220 14% 15% / 0.19;
  --border-subtle: 220 14% 15% / 0.07;
}
```

### 2.3 使用规则

- 页面基底用 `--background`；侧栏、列表与常驻面板用 `--surface`；仅浮层使用 `--surface-elevated`。
- 层级优先通过 1px `--border` 和 3–6% 明度变化表达，卡片默认**无阴影**。
- `--primary` 只用于确认、当前选中、焦点和链接；同一可视区域内不超过一个主要强调动作。
- 成功、警告、危险色仅表达状态，不得作为大面积装饰色。

## 3. 排版与图标

| 场景 | 字号 / 行高 | 字重 | 规则 |
|---|---|---|---|
| 页面标题 | 20px / 1.25 | 600 | 只出现在工作区标题栏 |
| 区块标题 | 14px / 1.4 | 600 | 用于列表分组与面板标题 |
| 列表标题 | 13px / 1.4 | 500–600 | 单行截断 |
| 正文 | 13px / 1.55 | 400 | 阅读宽度最大 720px |
| 辅助信息 | 12px / 1.45 | 400 | 来源、状态、说明 |
| 元数据 | 11px / 1.4 | 400 | 时间、计数、快捷键 |

- 字体：`Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, sans-serif`。
- 代码与 ID：`"Geist Mono", "JetBrains Mono", monospace`。
- 使用 Lucide 图标，常规尺寸 14–16px；图标按钮必须提供 `aria-label` 或可见文本。
- 标题字距 `-0.01em`；不要使用全大写作为主要信息，分组标签可使用 11px 全大写。

## 4. 空间、布局与响应式

### 4.1 间距刻度

仅使用 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。

### 4.2 桌面工作台骨架

```
┌───────────────┬──────────────────────────────────┬─────────────────┐
│ 全局侧栏      │ 工作区：标题 / 工具栏 / 主列表   │ 检查器（按需）  │
│ 224–248px     │ minmax(0, 1fr)                   │ 320–380px       │
└───────────────┴──────────────────────────────────┴─────────────────┘
```

- 全局侧栏宽度 224–248px，固定但可折叠；包含工作区导航、集合、底部账户/设置。
- 工作区上方标题栏高度 48–56px，包含页面标题、状态与少量上下文操作。
- 主列表不放进独立大卡片：用容器背景、顶部分隔与行分隔组织。
- 详情检查器只在选中对象时打开；关闭后主工作区自动扩展。
- 内容阅读区域最大宽度 720px，避免记忆正文横跨整个屏幕。

### 4.3 断点

- `> 1080px`：三栏可用。
- `720–1080px`：隐藏或抽屉化检查器，保留侧栏和主工作区。
- `< 720px`：侧栏变为顶部紧凑导航，详情使用覆盖式抽屉或独立路由；禁止三栏压缩。

## 5. 核心组件规范

### 5.1 导航与侧栏

- 导航项高度 30–32px，左右内边距 8px，图标与文本间距 8px。
- 当前项：`--surface-active` 背景 + 左侧 2px `--primary` 指示条；不可只改变文字颜色。
- 悬停项：`--surface-hover` 背景；非当前项默认使用 `--foreground-secondary`。
- 集合树使用缩进表达层级，不使用文件夹拟物图形；计数仅在有决策价值时显示。

### 5.2 顶栏与工具栏

- 顶栏用于“当前位置 + 1 个主要操作 + 少量工具”，不要放完整导航。
- 工具栏控件统一高度 28–32px，按优先级排列：主按钮、次按钮、图标按钮、更多菜单。
- 命令入口使用 `⌘K` / `Ctrl+K` 提示；不能用纯图标替代高频可发现操作。

### 5.3 列表、时间线与检索结果

- 列表行高度 36px（纯元数据）或 56–72px（包含摘要）；不得使用无边界的卡片瀑布流。
- 行结构固定为：来源标识 → 主文本 → 次要元数据 → 悬停操作。
- 悬停操作默认隐藏或弱化，避免每一行持续出现按钮噪声。
- 选中行使用 `--surface-active`，键盘焦点使用 2px `--ring`；两种状态必须可区分。
- 检索结果应突出匹配摘要、来源、时间和相关度，禁止只展示内部 ID。
- 空状态说明当前筛选为何无结果，并提供一个明确的下一步动作。

### 5.4 详情与编辑器

- 详情面板标题栏固定，正文滚动；编辑和阅读不混用视觉层级。
- 编辑态显示明确的“保存 / 取消”，未保存内容需有状态提示。
- 详情元数据使用 11–12px 弱文本；标签为 `--muted` 背景、`--radius-sm` 的紧凑徽标。
- 破坏性操作放在更多菜单或二次确认中，使用 `--danger`，不与保存按钮并排抢焦点。

### 5.5 输入、按钮与菜单

- 输入高度 32px；搜索输入可为 36px。背景 `--surface`，边框 `--border`。
- 焦点状态：边框或环切换为 `--ring`，保持 2px 清晰可见焦点环。
- 主按钮：`--primary` 背景 + `--primary-foreground` 文字；只用于提交或创建。
- 次按钮：`--surface` + `--border`；幽灵按钮仅在工具栏与行内操作中使用。
- 下拉菜单和弹窗：`--surface-elevated`、`--border`、`--shadow-md`、`--radius-lg`。

## 6. 状态、反馈与动效

- 请求中：在原按钮内显示简短状态并禁用重复提交；不要以整页遮罩阻断阅读。
- 成功：在操作附近显示可消退的 12px 状态文字或 toast；不要使用长时间动画。
- 失败：保留用户输入，提供可读错误和重试路径。
- 同步：使用小型状态点或文字，不使用持续旋转的大图标。
- 常规 hover、颜色过渡：100–150ms `ease-out`。
- 弹窗、抽屉：150–200ms `cubic-bezier(0.16, 1, 0.3, 1)`，位移不超过 8px。
- `prefers-reduced-motion: reduce` 时关闭非必要位移和渐显。

---

## 7. 可访问性与质量门槛

- 交互元素必须可键盘到达，焦点不可被 `outline: none` 隐藏。
- 图标按钮必须有 `aria-label`；状态变化使用 `aria-live` 或可见文本。
- 最小点击区域 28×28px；常用操作推荐 32px 高。
- 文本与背景、边框与背景必须保持足够可辨识度；不能只依赖颜色传达状态。
- 每次 UI 改动后检查：1440px 桌面、1024px 窄桌面、390px 移动宽度；验证溢出、选中、禁用、错误、空状态和键盘焦点。

---

## 8. @nexus/ui 落地要求

1. token 由 `packages/ui` 的全局样式导出；应用只引用 token，不复制色值。
2. 优先在 `@nexus/ui` 建立 Button、Input、IconButton、SidebarItem、ListRow、Badge、Dialog、Sheet 等基础组件，再由业务应用组合。
3. 使用 Radix 原语实现 Dialog、Menu、Popover、Select、Tooltip 的焦点管理和键盘行为。
4. 所有应用默认暗色；亮色切换只能覆盖 token。
5. 新增组件必须先满足本文件的状态与可访问性规则，再进入业务页面。

## 9. Orbit 页面映射

| Orbit 区域 | 使用模式 |
|---|---|
| 检索中心 | 顶栏 + 主要搜索输入 + 可选筛选工具栏 + 结果列表 + 详情检查器 |
| 时间线 | 分组列表、来源筛选、日期分隔、可选详情检查器 |
| 集合 | 树形侧栏 + 主列表；集合管理放进上下文菜单或独立工具栏 |
| 记忆编辑 | 详情检查器或专用工作区；明确保存 / 取消 / 未保存状态 |
| 快速记录 | 紧凑输入区或命令面板，不应抢占主列表阅读面积 |

后续 UI 实现必须以本文件替代此前的“暗色高级简约”描述；已有页面应逐步迁移到本文件的三栏工作台、列表密度和渐进揭示规则。
